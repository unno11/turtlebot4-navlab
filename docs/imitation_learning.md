# 模仿学习基线（行为克隆）

用模仿学习替换 Nav2 的局部控制器，在**同一套目标、同一套评测口径**下与 MPPI / RPP / Graceful 比较。

[返回首页](../README.md) · [局部控制器对比](controller_comparison.md) · [实验记录](experiment_logging.md)

## 为什么做

基线的 24 次试验全部成功，控制器对比里也没有稳定性证据 —— 这个评测台目前只能证明"系统能跑通"，还证明不了它能区分**学习出来的策略**和**手写的控制律**。

行为克隆是这个方向上最小的一步：专家信号现成（MPPI 的成功运行），评测协议也现成（8 目标 + 同一判定规则）。做完之后，评测台第一次被用来评价一个"学到了参数"的东西。

## 方法

| 环节 | 做法 |
| --- | --- |
| 专家 | MPPI 跑成功的运行，逐 tick 记录 |
| 观测（65 维） | 激光 60 分箱（min-pool，截断 6 m，归一化）+ 前视点（base 系 x,y，前视 0.7 m）+ 到目标距离 |
| 动作（2 维） | `(v, ω)`，标签取 `/cmd_vel` —— 真正到达底盘的那条指令 |
| 模型 | 65→128→128→2 的 MLP，torch 训练，导出 numpy 权重 |
| 部署 | `policy_node.py` 用 numpy 做前向，运行时不依赖 torch |
| 评测 | 全局规划仍由 Nav2 `compute_path_to_pose` 提供（每 2 s 重规划），策略只替换控制器 |

观测布局定义在 `scripts/bc_common.py`，采集、训练、部署三处共用 —— 训练和部署的特征一旦错位，策略会静默失效，所以只允许有一处定义。

## 数据流

```
controller_server ─→ /cmd_vel_nav ─→ velocity_smoother ─→ /cmd_vel_smoothed
                                   ─→ collision_monitor ─→ /cmd_vel ─→ 底盘
```

- **采集**订阅 `/cmd_vel`（末端指令，即实际产生运动的指令）
- **策略**发布到 `/cmd_vel_nav`，因此也走过 `velocity_smoother` 与 `collision_monitor`，与 Nav2 共用同一条安全链

## 实现时踩到的四个坑

1. **`/cmd_vel` 是 `TwistStamped`。** 首版按 `Twist` 订阅，采集到 2217 帧观测但动作全是 0 —— 采集器没报错，文件也是合法的。判断方式是统计动作非零占比，不是看文件是否存在。已丢弃重采。
2. **策略必须发 `/cmd_vel_nav`，不是 `/cmd_vel`。** 直接发 `/cmd_vel` 会绕过速度平滑和碰撞监控，评测条件与 Nav2 基线就不一样了。
3. **`bt_navigator` 刚 active 时会拒目标。** 一次性 `send_goal` 被 rejected，需要等 8 s 重发；采集脚本现在最多重试 3 次。
4. **`Parameter("use_sim_time", True)` 需要显式类型**（`Parameter.Type.BOOL`），否则 rclpy 直接抛 `TypeError`。

## 复现

```bash
cd ~/turtlebot4_ws/src/turtlebot4-navlab

# 1. 采演示：每个目标重启整套仿真，Nav2 开车，采集器在旁边记录
GOALS="G01 G02" ./scripts/collect_demos.sh          # → results/demos/*.npz

# 2. 训练（需要 torch，CPU 即可）
~/.venvs/navlab-il/bin/python scripts/train_bc.py \
  --demos results/demos --include G01,G02 \
  --out results/policy/bc_g01g02.npz                # → 权重 + 同名 .json 报告

# 3. 在线评测：策略当控制器，规划仍走 Nav2
./scripts/eval_policy.sh results/policy/bc_g01g02.npz G01 results/policy_eval/bc_G01.json
```

`results/demos/`、`results/policy/`、`results/policy_eval/` 都不入库：它们是本机数据，和 `results/runs/` 一样只留在本地。

## 离线结果

| 项目 | 值 |
| --- | --- |
| 演示条数 | 2（G01、G02） |
| 样本数 | 训练 ~3900 / 验证 ~700（每条演示的时间尾部 15% 留出） |
| 验证 MAE | v **0.081 m/s**，ω **0.129 rad/s** |
| 验证损失 | 1.4–24（抖动大，见下） |

验证损失抖动大的原因：切分是按时间做的，验证段落落在"接近目标、速度接近 0"的分布上，与训练段的分布不同。这不是模型不稳定，而是这个切分方式测的是外推而不是同分布误差。

### 修复两个缺陷后（65 维）

审查代码时找到两处可修缺陷，都不是模型容量问题：

| 缺陷 | 表现 | 修法 |
| --- | --- | --- |
| **ω 既是输入又是标签** | 观测最后一维和标签的第二维取自同一条 `cmd_vel`，网络只需把输入抄到输出即可降低损失；闭环里这个拷贝自我反馈，实测 ω 冻结在 **0.0056 rad/s** —— 车不会转弯 | 观测里删掉 ω，模型必须从几何量（前视点偏角）推断转向 |
| **重规划周期 = 判旧阈值** | 每 3 s 重规划，而规划年龄 > 3 s 就停车，两者相等 → 每次重规划前必然停车，走走停停 | 重规划改为 2 s，判旧阈值放宽到 4.5 s |

修复后的同一次评测：

| 项目 | 结果 |
| --- | --- |
| 速度 | v = **0.254 m/s**，专家 0.26 —— 贴上了 |
| 转向 | ω 不再冻结，随前视点偏角变化 |
| 路线 | 走通全程并越过目标，终点 (7.06, 7.77) |
| 评测判定 | **FAILED**：240 s 仿真内未进入 0.25 m 判定圈 |
| 行驶距离 | **17.23 m**（规划路线 7.88 m，即绕行 2.2 倍） |
| 宿主 | RTF ≈ 0.24（240 s 仿真 / 1003 s 墙钟） |

### 剩余差距在哪

从目标旁约 **0.6 m** 处擦过，然后继续前进、绕过目标才回来 —— 两个问题：

1. **横向精度不足**：8 m 的距离上累积约 0.6 m 偏移，超过 0.25 m 的判定圈。
2. **没有停车行为**：专家在终点减速停车，策略没有学到"到点即停"，而是继续沿规划走。

两者都是行为克隆在分布外的典型表现，也正是 DAgger 要解决的部分：需要专家在"策略走偏之后的状态"上给出纠正动作。

### 一处已撤回的结论

第一版评测曾记录"策略输出 v≈0.05，比专家慢 4 倍"，并写进本文档。那次评测跑在负载 20–45 的宿主上（反复启动、强杀仿真造成），单次 `cmd_vel` 采样与 odom 推算的速度都被压低。**空闲宿主复测、并在修复缺陷后，速度与专家基本一致；"速度塌陷"这个判断不成立，已撤回。**

### 离线指标的参照

| 版本 | 观测维度 | 验证 MAE (v / ω) |
| --- | --- | --- |
| v1（含 ω 输入） | 66 | 0.081 / 0.129 |
| v2（去掉 ω 输入） | 65 | 0.133 / 0.100 |

v2 的 v 误差变大是预期的：拿掉 ω 之后，"当前在多快地转"不再直接可见，只能从几何量推断。但 v1 更低的误差是靠抄输入换来的，闭环证据表明那是个退化解，不是更好的策略。

## 局限

- **闭环一次都没有进入判定圈。** 修复 ω 缺陷后策略能走完全程（终点在目标旁 0.6 m 处擦过），但 240 s 仿真内未进入 0.25 m 判定圈，行驶距离是规划路线的 2.2 倍。因此没有成功率数字可报告 —— 这份文档记录的是"管线可用 + 两处缺陷已修 + 失败分析"，不是"策略可用"。
- **只有 2 条演示、单一目标族。** 学到的策略对应的是"从 S0 出发、走这两条路线"的经验，不是通用控制律。
- **没有 DAgger 或误差修正。** 行为克隆的经典问题是状态分布偏移：一旦策略偏离专家轨迹，它看到的状态就从没在训练里出现过，误差会累积。
- **没有视觉输入**，观测里只有激光与几何量；与具身智能常见的视觉-语言-动作路线还差很远。
- **目标判定只看到达距离（0.25 m）**，未包含朝向误差，与基线的判定口径不完全一致。
- 演示来自 MPPI 单次运行，继承该次运行的宿主条件（RTF 0.19–0.30）。

## 下一步

1. 补足演示：每个目标族至少 1 条（simple / turning / narrow / long），再做"演示条数 → 成功率"的曲线。
2. 加 DAgger 循环：用策略自己跑，把偏离后的状态交给专家标注，再训练。
3. 评测口径与基线对齐：加入朝向误差、恢复次数（策略无恢复行为，需要单独说明）。
